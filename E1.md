# E1 handoff — live context-expansion acceptance on Brev

## Objective

Prove that a real Nemotron endpoint can start with only the incident symptom,
request the missing diagnostic evidence through Nexus tools, and identify a real
parser/template mismatch without receiving a prewritten diagnosis.

This is the live acceptance step for bounded context expansion. The local tests
already validate controller behavior with scripted model turns and a fake target.
Those tests are necessary, but they do not count as live acceptance.

## Required result

Starting prompt:

```text
The target inference endpoint returns HTTP 200, but the visible tool-call canary
produces no structured tool call. Diagnose the incident using the available
read-only tools.
```

The live run must establish all of the following:

1. the target request returns HTTP `200`;
2. the structured response contains zero usable tool calls;
3. the raw pre-parser generation contains a recognizable call-shaped payload;
4. the effective serving configuration contains an incompatible parser/template
   pair;
5. Nemotron requested the relevant evidence itself;
6. the final `PLAN` diagnosis cites controller-issued evidence IDs;
7. no hidden canary, unrestricted shell, unrestricted filesystem, or secret was
   exposed to the model.

The expected evidence chain is:

```text
visible canary: HTTP 200 + zero parsed calls
  -> raw generation: call-shaped payload exists
  -> launch configuration: parser/template mismatch
  -> evidence-backed parser/template diagnosis
```

## Important repository status

The repository currently contains:

- the real vLLM/Nemotron client;
- the agent controller and evidence ledger;
- all diagnostic tool schemas and policy limits;
- scripted local acceptance tests.

The repository does **not** yet contain a Brev-specific `DiagnosticBackend`
adapter or a live diagnostic runner. Do not report Checkpoint 2 as passed by
running only the unit tests or topology smoke test. The Brev integration details
collected below are required to finish that adapter.

## 5. Provide the six read-only backend operations

The Brev adapter must implement the `DiagnosticBackend` protocol from
`nexus/agent/diagnostic_tools.py`. Each operation must return a JSON object.

### `get_status()`

Required shape:

```json
{
  "healthy": true,
  "services": ["target-a"],
  "readiness": "ready"
}
```

### `run_canary(case)`

Only `visible_tool_call` may be exposed to the model.

Required shape:

```json
{
  "case": "visible_tool_call",
  "request_id": "req-184",
  "http_status": 200,
  "parsed_tool_call_count": 0,
  "structured_response": {
    "tool_calls": []
  }
}
```

The `request_id` must correlate the structured response, request trace, and raw
generation from the same request.

### `get_launch_config(service)`

Return the effective, redacted configuration—not merely intended environment
values.

Required shape:

```json
{
  "service": "target-a",
  "image_digest": "sha256:<digest>",
  "model_revision": "<revision>",
  "enable_auto_tool_choice": true,
  "tool_call_parser": "<active-parser>",
  "chat_template": "<active-template-or-identifier>"
}
```

Do not return API keys, registry credentials, authorization headers, tokens, or
the complete process environment.

### `get_request_trace(request_id)`

Required shape:

```json
{
  "request_id": "req-184",
  "http_status": 200,
  "structured_response": {
    "tool_calls": []
  },
  "parser_result": "zero tool calls"
}
```

### `read_raw_generation(request_id)`

Required shape:

```json
{
  "request_id": "req-184",
  "text": "<raw model generation before structured tool-call parsing>"
}
```

This is the most important integration requirement. The ordinary OpenAI-style
response may contain only the post-parser structured result. If the current
gateway or vLLM setup does not preserve pre-parser text, add bounded capture at
the harness/gateway layer. Do not substitute a fabricated fixture for the live
acceptance run.

### `read_logs(service, since, pattern, limit)`

Required shape:

```json
{
  "service": "target-a",
  "since": "10m",
  "pattern": "parser|tool",
  "limit": 200,
  "lines": ["<bounded redacted log line>"],
  "truncated": false
}
```

Enforce the requested limit, redact secrets, and never return an unrestricted
container log dump.

## 6. Reproduce both target states

From a clean reset, demonstrate and preserve evidence for:

### Healthy state

- readiness passes;
- the visible canary returns HTTP `200`;
- at least one structured tool call is parsed correctly.

### Broken state

- change only the incident-declared parser/template contract;
- readiness still passes;
- the identical visible canary returns HTTP `200`;
- structured tool-call count becomes zero;
- the raw generation still contains a call-shaped payload.

Run reset → inject → reproduce three consecutive times if time permits. Record
the exact reset and injection operations and whether all three runs matched.

## 8. Final live acceptance

After E1 wires the Brev adapter and live runner using the interface above, rerun
from a clean injected state. The final run is accepted only when the event log
shows that real Nemotron—not a `ScriptedNemotronClient`—requested the canary,
raw generation, and serving configuration and then returned an evidence-backed
parser/template diagnosis.

Preserve from the final run:

```text
events.jsonl
evidence/*.json
console summary
commit SHA
container image digest
```

The model's decision should be `PLAN` with real evidence IDs. The controller may
then remain at `PLAN`, enter `PRECHECK` when repair policy is configured, or stop
at `REQUIRES_APPROVAL` when automatic repair is intentionally disabled. No
mutation is required to pass this context-expansion acceptance.

## Stop conditions

Stop and report to E1 instead of improvising if:

- pre-parser raw generation cannot be captured;
- the injected failure also breaks readiness or returns a non-200 response;
- healthy and broken runs use different model weights, prompts, seeds, or cases;
- the only available interface exposes unrestricted shell or filesystem access;
- any required artifact contains credentials;
- Nemotron is not making native tool calls through the configured vLLM parser.
